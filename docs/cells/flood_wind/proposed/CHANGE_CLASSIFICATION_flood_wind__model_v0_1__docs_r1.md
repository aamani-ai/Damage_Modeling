The requested work creates a governed flood × wind research cell and documents a reusable
flood-electrical component substrate. It does not publish a curve, alter a current artifact, or change a
Hazard consumer pin.

## Why this is not a model release

No representative evidence chain currently joins component-local flood state to inspected disposition and
same-unit direct repair or replacement cost. Values, ownership, component inventory, and local elevations are
also unresolved. Therefore model v0.1 has zero curve records and fails closed.

## Why the shared substrate is not a schema change yet

The common layer is documentation and authoring guidance only. Current runtime artifacts remain self-contained
cell bundles. An external shared-response reference would change loading, version propagation, rollback, and
consumer behavior, so that later work must be classified separately.

## Version consequence

This new cell starts at model v0.1 / docs r1. Flood-solar remains model v1.0 / docs r4, and its canonical
artifact is used only as a pinned neighboring-cell candidate. A future output-bearing flood-wind release must
perform semantic-version review and cannot silently replace this scaffold.

- no Hazard M3 or M4 edit;
- no current-cell replacement;
