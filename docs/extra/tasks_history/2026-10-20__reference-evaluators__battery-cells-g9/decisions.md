# Decisions — reference evaluators for the two battery cells (G9), 2026-10-20

*Agent decisions about how the evaluators read the artifacts. The owner rulings they rest on are `DCD-D09`
(evaluators live here) and the cells' own contracts (BW-Q01, BWF-Q01, the v1.0 capability conditions).*

| # | Decision | Why |
|---|---|---|
| D1 | Shape both evaluators like the per-cell house evaluators (`flood_real_estate_curve_eval.py`, `hail_real_estate_curve_eval.py`): standard library, `DamageCallError.code`, `evaluate_damage_call(artifact, request)` → damage emit v2, a two-argument CLI; add a record-grain `evaluate_curve_record` | The dashboard sampler needs every record at pathway × failure-unit grain without composing requests; consumers need the fail-closed call |
| D2 | Reject every request field outside the declared contract (`REQUEST_FIELD_UNSUPPORTED`), naming frequency fields (`FREQUENCY_FIELD_NOT_ALLOWED_IN_DAMAGE_CALL`) | Both cells' metadata list frequency, heat-flux, duration, height, shielding and discount inputs as unsupported, "not hidden converters or optional credits"; Hazard's wildfire consumer rejects unknown fields the same way |
| D3 | Hurricane: require an explicit `response_hypothesis_id` and `resistance_scenario`; the requested scenario fills `scalar_central_dr`, all three scenarios are reported in `scenario_drs`, nothing is averaged, and state probabilities are not emitted | `default_response_hypothesis` is null; the sensitivities are unweighted; the capability populates `scalar_mean` only and declares no intrinsic spread. State probabilities stay available from `evaluate_curve_record` for audit |
| D4 | Hurricane demand: accept the preferred `pressure_ratio`, or a 3-s gust pair squared here exactly as Hazard's bridge does (`(event/reference)**2`); require a non-empty `demand_basis_id` and record it | v1.0's `required_local_demand_basis_id` reads "qualified comparable pressure reference declared by consumer": a declaration this repository cannot judge, only require and carry. The pair mode lets the Hazard comparison feed identical inputs |
| D5 | Hurricane demand outside [0, 2] → withheld result with `AXIS_OUTSIDE_VALID_RANGE` and the record identified; malformed demand (string, boolean, NaN, half a pair) → error | The artifact says "withhold outside range; no clamp"; the house treats malformed requests as errors |
| D6 | Wildfire: the request selector is `evaluation_contract.reference_id` (`BESS_LFP_R1_WILDFIRE_ORDINAL_V1`); the records' `selector_match.reference_id` (`…_LOCAL_V0_1`) is echoed as `selectors_used.curve_selector_reference_id`, and record-level `metadata_flags` are surfaced under `input_quality`, not asserted as the call's flags | The metadata table names the V1 id as the required `selector_id`, Hazard's v1.0 binding requires it, and the records were preserved byte-for-byte from v0.1 with their old id and `LOCAL_TEST_ONLY_NOT_CANONICAL` flag. The evaluation contract's `limitation_flags` are the current contract; the stale flags are kept visible, not dropped |
| D7 | Wildfire class state: an integer or integer-valued float 0–6; booleans, strings, fractions, NaN, missing and out-of-range states raise `EXACT_FSIM_CLASS_STATE_REQUIRED`; nothing is interpolated | The cell's own vocabulary ("booleans/strings/fractions/missing/out-of-range rejected") and Hazard's status string |
| D8 | Withheld units return the artifact's own reason codes: the union of `failure_units[].withheld_reason_codes` and the capability's `withheld_failure_units[].reason_codes` (one code for hurricane, two for wildfire), null DR, null curve id | The brief: "unsupported pairs return the artifact's reason code"; no code is invented |
| D9 | Optional `same_unit_value_usd` adds `exposure_used.expected_loss_usd` (and per-scenario dollars for hurricane); `load_value_binding` verifies the artifact's pinned SHA before handing out unit values | Scenario loss is conditional on "unique physical unit and same-unit value"; the wildfire known answers carry dollars that must be proven, and the evaluator must not bake values in |
| D10 | Validators use 1e-12 on the damage ratio and 1e-6 USD, and print the observed deviations (1.9e-17 and 0 / 1.5e-11) | Neither known-answer file declares a tolerance (standard 20 §6 asks for one); the chosen bounds sit far above float noise and far below any physical meaning |
| D11 | Cross-check Hazard by running its consumers in Hazard's own venv from the scratchpad, comparing at Hazard's own demand values and through the gust pair; record inputs, outputs and differences in `hazard_consumer_comparison.md` per cell, with the harness inline | The brief allows running Hazard's code through its venv but forbids importing or copying it; committing a Hazard-importing module here would cross that line |
| D12 | Validate the request fully (hypothesis, scenario among the records' declared ids, exact state) before a withheld unit answers | Fail closed in the same order as Hazard; the hurricane validator caught the first draft letting an unknown scenario through on a withheld unit |
| D13 | Leave the catalogue entries alone | The catalogue README defines `checks` as outside checks (NRI, NFIP, DINS, financial range); an implementation-parity check is not evidence about the curve, and `files` has no evaluator slot. Editing an entry would also require rebuilding `CATALOGUE.md` |
| D14 | Leave the dashboard plan's Phase 3 checkbox untouched | The plan folder is shared with the parallel dashboard session; tick it on merge |
